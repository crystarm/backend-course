# 3 лабораторная работа

**Работа выполняется на основе предыдущей 2 лабораторной. Вариант сохраняется.**

В предыдущей лабораторной работе вы реализовали репозиторий для работы с базой данных через JDBC и обеспечили поддержку базовых CRUD-операций.
Теперь важно реализовать сервисный слой и проверить корректность его работы с помощью тестов.

## Задание

Работа состоит из 2-х этапов:

### 1) Сервисный слой

Необходимо создать класс-сервис, реализующий бизнес логику. То есть оборачивающий репозиторий дополнительной функциональностью.
Сервис должен реализовывать интерфейс (вместо entity используйте свою сущность):
```java
public interface EntityService {
    // Create (возвращает id созданной записи)
    int save(/* поля сущности */);

    // Read (бросает исключение, если запись не найдена)
    Entity findById(int id);

    // Read (бросает исключение, если запись не найдена)
    Entity findByField(String field);

    List<Entity> findAll();

    // Update (используйте id для поиска сущности и бросайте исключение, если запись не найдена)
    void update(Entity entity);

    // Delete
    void deleteById(int id);
}
```
Для случая, когда сущность не обнаружена — необходимо создать и бросить собственное исключение.

Сервис должен принимать в конструкторе экземпляр репозитория и присваивать его в private final поле.

### 2) Unit-тесты для сервиса

**Необходимо написать отдельные unit-тесты на каждый метод созданного сервиса.**

Тесты должны проверять все крайние случаи, например когда запись не была найдена и было брошено исключение.
Необходимо "замокать" зависимость сервиса, то есть репозиторий. Тесты не работают с реальной БД.
Каждый тест должен работать независимо от других.

Зависимости:
+ Используйте тестовый фреймворк JUnit
+ Для контроля данных используйте методы класса org.junit.jupiter.api.Assertions
+ Для создания фиктивных объектов используйте mockito

## Дополнительное задание (не отменяет основное)

Сделать rest-http-сервис на основе полученного приложения. Реализовать слой контроллера.
Можно использовать для этого любую библиотеку или фреймворк (самый простой вариант — Javalin/Jooby).

В случае использования Spring — обязательно написать mvc-тесты (используйте @SpringBootTest + MockMvc).
