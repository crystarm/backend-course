# 3 лабораторная работа

**Вариант сохраняется с лабораторной №2.**

В предыдущей лабораторной работе вы реализовали репозиторий для работы с базой данных через JDBC и 
обеспечили поддержку базовых CRUD-операций.
Теперь важно научиться реализовывать сервисный слой, настроить web-сервер и проверить корректность работы приложения с помощью тестов.

## Подготовка

Работа выполняется в том же личном монорепозитории, но нужно создать отдельный модуль для 3 лабораторной.
Скопируйте в новый модуль все необходимые файлы из модуля 2 лабораторной.

## Задание

Работа состоит из 3-х этапов:

### 1) Сервисный слой

Необходимо создать класс-сервис, реализующий бизнес логику. То есть оборачивающий репозиторий дополнительной функциональностью.
Сервис должен реализовывать интерфейс (вместо entity используйте свою сущность):
```java
public interface EntityService {
    // Create (возвращает id созданной записи)
    int save(/* поля сущности */);

    // Read (бросает исключение, если запись не найдена)
    Entity findById(int id);

    // Read (бросает исключение, если запись не найдена)
    Entity findByField(String field);

    List<Entity> findAll();

    // Update (используйте id для поиска сущности и бросайте исключение, если запись не найдена)
    void update(Entity entity);

    // Delete
    void deleteById(int id);
}
```
Для случая, когда сущность не обнаружена — необходимо создать и бросить собственное runtime-исключение.

Сервис должен принимать в конструкторе экземпляр репозитория и присваивать его в private final поле.

### 2) Web

Сделать rest-http-сервис на основе полученного приложения. Реализовать слой контроллера.
Можно использовать для этого любую библиотеку или фреймворк, рекомендуются:
* Javalin
* Jooby
* spring-boot-web — в этом случае начисляются дополнительные баллы

### 3) Unit-тесты для сервиса

Необходимо написать отдельные unit-тесты на каждый метод **созданного класса-сервиса.**

Тесты должны проверять все крайние случаи, например когда запись не была найдена и было брошено исключение.
Необходимо "замокать" зависимость сервиса, то есть репозиторий. Тесты не работают с реальной БД.
Каждый тест должен работать независимо от других.

Зависимости:
+ Используйте тестовый фреймворк JUnit
+ Для контроля данных используйте методы класса org.junit.jupiter.api.Assertions
+ Для создания фиктивных объектов используйте mockito

В качестве дополнительного задания, в случае использования Spring — напишите mvc-тесты (используйте @SpringBootTest + MockMvc).
Отдельным плюсом будет использование TestContainers.

## Правила оценивания

* 10 баллов — базовое выполнение работы (класс-сервис, web на Javalin/Jooby, unit-тесты), ответы на вопросы по коду
* 3 балла — использование spring-boot-web
* 3 балла — mvc-тесты для spring-boot-web
* 4 балла — использование TestContainers

Итого вы можете получить до 20 баллов.
