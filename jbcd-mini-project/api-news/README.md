# Сервис Новости (api-news)

Микросервис, ответственный за управление новостями в системе.
Это классическое CRUD приложение, которое предоставляет REST API для публикации и просмотра новостей.

## Технологический стек

- **Spring Data JDBC**: Для взаимодействия с базой данных PostgreSQL. Простой и эффективный способ работы с реляционными
  данными.
- **Redis (Spring Cache)**: Для кеширования списка новостей и конкретных постов, чтобы снизить нагрузку на БД.
- Интеграция с `api-captcha` для защиты от спама.

## API Эндпоинты

### 1. Получение всех новостей

`GET /news`

**Назначение:** Возвращает список всех опубликованных новостей.

- **Принимает:** Параметры не требуются.
- **Возвращает:** Объект `NewsEventList`, содержащий коллекцию новостей.
- **Примечание:** Результат кешируется. Если список изменится, кеш будет сброшен (инвалидация).

### 2. Получение новости по ID

`GET /news/{id}`

**Назначение:** Позволяет получить детальную информацию об одной новости.

- **Принимает:** `id` новости в пути запроса (Path Variable).
- **Возвращает:** Объект `NewsEvent`.
- **Ошибки:** Если новость не найдена, вернет 404 (через Global Exception Handler).

### 3. Создание новости

`POST /news`

**Назначение:** Создает новую новость в системе.

- **Принимает:** JSON-объект в теле запроса со следующими полями:
    - `title` (String): Заголовок новости (1-100 символов).
    - `message` (String): Текст новости (1-4000 символов).
    - `solvedCaptchaId` (UUID): Идентификатор капчи, которую пользователь успешно решил ранее.
- **Возвращает:** Объект `NewsEvent` (созданную новость с присвоенным ID).
- **Логика проверки:** Сервис обращается к `api-captcha` для подтверждения, что капча с указанным ID действительно
  решена и не была использована ранее. Если проверка не проходит — новость не создается.
